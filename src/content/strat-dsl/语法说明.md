# 攻略 DSL 语法

攻略文件使用 UTF-8 编码。空行可以自由添加，`//` 开头的行是注释。

## 页面设置

```text
副本：07/necron
基准：00:00.000
```

## 时间轴

```text
分段：机制名称
分段（mechanic-id）：带页面锚点的机制名称
事件 00:07.146：【MT】将【Boss】拉到场中。
事件 00:12.000：【全员】引导手【伤害:90000:物理】【物理易伤:1】
攻击 00:10.000：自动攻击；伤害=55000；类型=物理
读条 00:15.000：全屏技能；时长=5.0；目标=全员；伤害=100000；类型=魔法
```

伤害类型可以是 `物理`、`魔法`、`特殊`。读条目标可以是 `全员`、`坦克`、`治疗`、`输出`。

完整读条可使用 `时长`、`目标`、`目标标签`、`伤害`、`类型`、`补充`、`徽章`、`徽章颜色`：

```text
读条 00:07.146：青之冲击；时长=5.7；目标=坦克；目标标签=一仇；伤害=210000；类型=魔法；徽章=死刑；徽章颜色=红
```

徽章颜色支持红、橙、琥珀、黄、青柠、绿、翠绿、青、蓝。

多个特殊目标和多个徽章可以使用 `目标内容` 与 `徽章组`：

```text
读条 00:09.173：经典铭心；时长=4.7；目标内容=【坦克:一仇】【坦克:二仇】；补充=【流血:15】【持续伤害:34000】；徽章组=45°扇形@翠绿|死刑@红
```

## 内容区块

正文行前需要两个空格，每一行会渲染成一个段落。

```text
机制（机制标题）：
  第一段说明。
  第二段说明。

解法（推荐解法）：
  具体处理方式。

说明（额外提醒）：
  容易忽略的细节。
```

卡片内的小标题通常配合技能标记：

```text
机制：
  小标题：《青之冲击》
  对【坦克:一仇】的大范围扇形死刑，每段附带【魔法易伤:5】
```

## 行内标记

```text
【Boss】 【MT】 【ST】 【H1】 【H2】 【D1】 【D2】 【D3】 【D4】 【全员】
【坦克:一仇】 【近战:D1】 【远敏:D3】 【法系:D4】 【治疗输出】
《技能名称》
==需要黄色高亮的内容==
【魔法易伤:5】 【物理易伤:1】 【流血】
【流血:15】 【持续伤害:34000】 【伤害:90000:物理】
【链接:#mechanic-id:跳转到某个机制】
【状态:07/m5s/214280.png:状态名称:24】
```

## 警告块

```text
警告：
  【绿字:这是一条绿色提示】
  普通文字，【红字:这部分需要特别注意！】
  【青字:也可以使用青色文字】
```

## 图片

路径从 `src/assets` 开始。常用宽度为 80、90、100、112、120、140、160、200。

```text
图片：07/necron/BlueShockwave_1.png；标题=站位示意图；替代文字=蓝色冲击波站位；宽度=120
```

图片可以独立显示，也可以缩进两个空格放进机制、解法或说明卡片中。

多张图片放在同一行时使用图片组，组内图片缩进四个空格：

```text
解法：
  图片组：宽度=120
    图片：07/necron/left.png；标题=左侧情况
    图片：07/necron/right.png；标题=右侧情况
```

图片需要紧跟在同一个段落内部时使用图文：

```text
机制：
  图文：判定后观察场地变化
    图片：07/necron/example.png；宽度=160
```

图片和多段正文左右排列时使用并排图文：

```text
解法：
  并排图文：07/m5s/deep_cut.png；宽度=90；边框=amber
    【MT】在【Boss】左前引导
    【ST】在【Boss】右前引导
```

## 引用框

引用正文缩进四个空格，每行是一个段落：

```text
解法：
  引用：
    1. 【MT】组去西侧
    2. 【ST】组去东侧
```

## 条件分支

条件标题缩进两个空格，分支内容缩进四个空格：

```text
机制：
  条件：【状态:07/m5s/214280.png:蹦迪】倒计时结束时
    若满足安全条件，则机制成功
    若不满足安全条件，则机制失败
```

状态图标路径从 `src/assets/buff` 开始，后面依次填写状态名称和可选层数。

## 多解法标签页

每个方案需要唯一 `id`。方案正文缩进四个空格，图片组内的图片再缩进两个空格：

```text
多解法（默认=解法：日野主流）：
  方案（解法：日野主流；id=solution-jp）：
    这是默认方案。
    图片组：宽度=100
      图片：07/example/jp-1.png；标题=第一步
      图片：07/example/jp-2.png；标题=第二步
  方案（解法：三五分摊；id=solution-35）：
    这是另一套方案。
```

访问带方案 `id` 的 URL 会自动打开对应标签页；点击标签时也会同步更新 URL hash。

## 可折叠时间明细

摘要写在括号内，内部事件缩进两个空格：

```text
折叠（Boss 连续发动8轮扇形）：
  事件 02:34.924：第1轮扇形【伤害:95000:魔法】
  事件 02:37.377：第2轮扇形【伤害:95000:魔法】
```

页面默认只显示摘要，读者点击“展开细节”后才会显示内部时间轴。

## 帧动画

需要展示机制的连续变化时，可以把多张图片写成一个可播放的帧动画：

```text
动画（间隔=1200；宽度=160；自动播放=否）：
  图片：07/m5s/arcady_night_fever/1.png；标题=钢铁与第一轮扇形
  图片：07/m5s/arcady_night_fever/2.png；标题=月环与第二轮扇形
  图片：07/m5s/arcady_night_fever/3.png；标题=钢铁与第三轮扇形
  图片：07/m5s/arcady_night_fever/4.png；标题=月环与第四轮扇形
```

- `间隔`：每帧停留的毫秒数，最小为 100，默认 1200。
- `宽度`：和普通图片相同，填写 Tailwind 的宽度数值，例如 `160`。
- `自动播放`：填写 `是` 或 `否`，默认不自动播放。
- 动画至少需要两张图片；每张图片仍可设置 `标题`、`替代文字` 和 `边框`。

页面会自动显示“上一步、播放/暂停、下一步、重置”和当前帧数，不需要作者编写 JavaScript。

## 复杂组件预设

预设是可选的逃生口，仅用于 DSL 暂时无法描述的交互式或特殊 Astro 组件。普通攻略内容不需要预设，`necron-demo.strat` 已经完全由正文 DSL 生成。

```text
预设 interactive-diagram：开始=02:12.908
```

不需要时间的静态预设可以省略 `开始`。预设名称必须先由开发者注册，普通编写者无需接触 Astro 文件。
